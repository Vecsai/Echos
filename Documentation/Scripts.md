# Скрипты-цепочки в Echos

Скрипты позволяют автоматизировать массовую обработку файлов: чтение → отправка модели → сохранение результата. С их помощью можно обработать 100 документов одной кнопкой, не открывая каждое сообщение вручную.

---

## Как открыть

- **Кнопка 📜** в верхней панели программы
- Или меню **⌨ Команды** → «Скрипты-цепочки»
- Или горячая клавиша (если настроена)

В открывшемся диалоге:
- Слева — список сохранённых скриптов.
- Справа — редактор тела скрипта и результаты выполнения.
- Внизу — кнопки «Сохранить», «Запустить», «Стоп».

---

## Основы

Каждая строка скрипта — **команда**. Строки с `#` в начале — комментарии, они игнорируются.

**Пример:**

```
# Это комментарий
READ C:\docs\report.txt
PROMPT Сделай краткое резюме
SAVE C:\docs\summary.md
```

**Как это работает:**

1. `READ` — читает файл, кладёт его текст в переменную `context`.
2. `PROMPT` — отправляет модели инструкцию + содержимое `context`. Ответ модели заменяет `context`.
3. `SAVE` — сохраняет текущий `context` в файл.

**Результат:** модель получила текст файла, обработала его, результат записан в новый файл.

---

## Команды

### READ путь

Читает файл с диска. Поддерживаемые форматы:
- **Текст:** `.txt`, `.md`, `.py`, `.json`, `.csv`, `.html`, `.log`
- **Документы:** `.pdf`, `.docx`, `.pptx`

Содержимое попадает в `context` — результат предыдущих команд **перезаписывается**.

**Пример:**

```
READ D:\documents\article.pdf
```


⚠️ Изображения (`.png`, `.jpg`) **не читаются**. Если нужно обработать картинку — используйте обычный чат с вложением.

---

### PROMPT инструкция

Отправляет модели инструкцию вместе с текущим `context`.

**Логика:**
- Если `context` не пустой — к инструкции добавляется содержимое `context`.
- Если `context` пустой — отправляется только инструкция.
- Ответ модели становится новым `context`.

**Примеры:**
```
PROMPT Сделай краткое резюме в 5 пунктах
PROMPT Переведи на английский, сохрани стиль автора
PROMPT Определи тональность текста: позитивная, нейтральная, негативная
PROMPT Найди все упоминания дат и выпиши их списком
```

⚠️ **PROMPT без инструкции** вызовет ошибку. Пиши хотя бы одно слово.

---

### SAVE путь

Сохраняет текущий `context` в файл. Файл создаётся, если его нет. Папки создаются автоматически.

**Примеры:**
```
SAVE D:\output\result.md
SAVE D:\output\{{file.stem}}_processed.txt
SAVE C:\Users\Me\Desktop\report_{{date}}.md
```


⚠️ Если родительская папка не существует — она будет создана.

---

### LOOP маска … END

Повторяет команды между `LOOP` и `END` для каждого файла, найденного по маске.

**Маска** — это glob-паттерн:
- `D:\logs\*.log` — все `.log` в папке
- `D:\texts\*.txt` — все `.txt`
- `D:\**\*.py` — **рекурсивно** все `.py` во всех подпапках
- `D:\data\report_*.csv` — файлы с префиксом `report_`

**Пример:**
```
LOOP D:\logs\*.log
READ {{file}}
PROMPT Найди все ошибки ERROR и выпиши их
SAVE D:\errors\{{file.stem}}_errors.md
END
```

**Что произойдёт:** для каждого `.log` в папке `D:\logs\`:
1. Прочитает файл.
2. Отправит модели задание.
3. Сохранит результат в `D:\errors\<имя-без-расширения>_errors.md`.

### Переменные внутри LOOP

| Переменная | Что это | Пример |
|---|---|---|
| `{{file}}` | Полный путь к файлу | `D:\logs\app_1.log` |
| `{{file.name}}` | Имя с расширением | `app_1.log` |
| `{{file.stem}}` | Имя без расширения | `app_1` |
| `{{file.ext}}` | Расширение | `.log` |
| `{{file.dir}}` | Папка | `D:\logs` |
| `{{index}}` | Номер файла в цикле | `1`, `2`, `3` |

### IF условие … ELSE … END

Проверяет текущий `context` и выполняет одну из ветвей.

**Пример:**
```
READ D:\input\status.txt
PROMPT Определи уровень: CRITICAL, WARNING или OK
IF содержит "CRITICAL"
SAVE D:\out\critical.txt
ELSE
SAVE D:\out\normal.txt
END
```


**Без ELSE** — ветка выполнится только если условие истинно:
```
PROMPT Проверь текст на наличие email-адресов
IF содержит "@"
SAVE D:\out\has_email.txt
END
```


### Поддерживаемые условия

| Условие | Что проверяет |
|---|---|
| `содержит "текст"` | Есть ли подстрока в контексте |
| `не содержит "текст"` | Нет ли подстроки |
| `начинается с "текст"` | Контекст начинается с указанного |
| `заканчивается на "текст"` | Контекст заканчивается указанным |
| `длина больше N` | Длина контекста > N символов |
| `длина меньше N` | Длина контекста < N символов |

**Английские синонимы** (можно писать по-английски):
- `contains "text"` = `содержит "text"`
- `not_contains "text"` = `не содержит "text"`
- `starts_with "text"` = `начинается с "text"`
- `ends_with "text"` = `заканчивается на "text"`
- `length_gt N` = `длина больше N`
- `length_lt N` = `длина меньше N`

⚠️ Текст для условий **обязательно в кавычках**. Регистр не важен — `ERROR` и `error` одинаковы.

---

### Вложенность

`LOOP` и `IF` можно вкладывать друг в друга.

**Пример с вложением IF в LOOP:**
```
LOOP D:\logs\*.log
READ {{file}}
PROMPT Определи уровень проблем: CRITICAL, WARNING или OK
IF содержит "CRITICAL"
SAVE D:\reports\critical\{{file.stem}}.md
ELSE
IF содержит "WARNING"
SAVE D:\reports\warning\{{file.stem}}.md
ELSE
SAVE D:\reports\ok\{{file.stem}}.md
END
END
END
```


**Важно:** каждому `LOOP` и `IF` соответствует **свой `END`**. Если забыть один — скрипт не запустится.

## Переменные даты и времени

Работают **везде**, не только в цикле:

| Переменная | Значение | Пример |
|---|---|---|
| `{{date}}` | Дата | `2026-10-10` |
| `{{time}}` | Время | `14-35-21` |
| `{{timestamp}}` | Unix timestamp | `1760103321` |

**Пример использования:**
```
READ D:\input\article.txt
PROMPT Сделай краткое резюме
SAVE D:\output\summary_{{date}}.md
```

## Полные примеры

### Пример 1: Резюме одного файла
```
READ D:\docs\report.pdf
PROMPT Сделай краткое резюме в 5 пунктах
SAVE D:\docs\summary_{{date}}.md
```


### Пример 2: Перевод всех текстов в папке
```
LOOP D:\texts\*.txt
READ {{file}}
PROMPT Переведи на английский, сохрани стиль автора
SAVE D:\texts_en\{{file.name}}
END
```


### Пример 3: Многошаговая обработка
```
READ D:\input\article.txt
PROMPT Выдели главные тезисы в виде списка
PROMPT На основе тезисов напиши краткую статью в 3 абзаца
PROMPT Переведи статью на английский
SAVE D:\output\article_en_{{date}}.md
```

Каждый `PROMPT` получает результат предыдущего и добавляет что-то своё. Это **цепочка** — отсюда и название.

### Пример 4: Сортировка логов по критичности
```
LOOP D:\logs\**\*.log
READ {{file}}
PROMPT Определи уровень проблем (CRITICAL/WARNING/OK)
IF содержит "CRITICAL"
SAVE D:\sorted\critical\{{file.name}}
ELSE
IF содержит "WARNING"
SAVE D:\sorted\warning\{{file.name}}
ELSE
SAVE D:\sorted\ok\{{file.name}}
END
END
END
```


### Пример 5: Проверка кода на баги
```
LOOP D:\project\**\*.py
READ {{file}}
PROMPT Найди потенциальные баги, ошибки типизации и плохие практики. Ответ дай в формате: список проблем с номерами строк. Если проблем нет — ответь одной строкой "OK".
IF не содержит "OK"
SAVE D:\bugs\{{file.stem}}_issues.md
END
END
```

### Пример 6: Расширенный анализ с двумя проходами
```
LOOP D:\emails\*.txt
READ {{file}}
PROMPT Определи, это спам или нормальное письмо
IF содержит "спам"
SAVE D:\emails\spam\{{file.name}}
ELSE
PROMPT Сделай краткое резюме письма и выпиши ключевые запросы
SAVE D:\emails\inbox\{{file.stem}}_summary.md
END
END
```

## Порядок выполнения

Скрипт выполняется **сверху вниз**, шаг за шагом. Результат каждой команды передаётся следующей через `context`.
```
[пусто]
↓
READ — читает файл → context = текст файла
↓
PROMPT — отправляет модели → context = ответ модели
↓
PROMPT — снова → context = новый ответ модели
↓
SAVE — сохраняет context
```

**Важно:** `context` **один на весь скрипт**. `PROMPT` перезаписывает его ответом модели. Если нужно накопить результаты — используйте несколько `SAVE` или сохраняйте в разные файлы.

---

## Ошибки и как их избежать

| Ошибка | Причина | Что делать |
|---|---|---|
| «Не найден END» | Забыли `END` у `LOOP` или `IF` | Посчитайте открывающие и закрывающие |
| «Неизвестная команда: …» | Опечатка в имени команды | Только `READ`, `PROMPT`, `SAVE`, `LOOP`, `IF`, `ELSE`, `END` |
| «Файл не найден: …» | Путь к файлу неверный | Проверьте `READ`-путь |
| «LOOP: не найдено файлов по маске» | Маска не совпадает ни с чем | Проверьте расширение или путь |
| «PROMPT без инструкции» | Пустая инструкция | Дайте модели хоть одну фразу |

## Советы

**1. Тестируйте на маленьких папках.**

Перед запуском на 500 файлов — прогоните на папке из 2-3 файлов. Убедитесь, что результат вас устраивает, и только потом запускайте на всём.

**2. Модель имеет значение.**

Для точных задач (анализ кода, извлечение данных) — используйте `qwen2.5-coder` или другую модель, заточенную под задачу. Для творческих — `qwen2.5:14b` или похожую.

**3. Следите за лимитами.**

Каждый `PROMPT` — это отдельный запрос к модели. Обработка 100 файлов = 100 запросов. Если модель медленная — процесс может занять часы.

**4. Не забывайте про стоп.**

Кнопка **Стоп** останавливает скрипт **после текущего шага**. Если сейчас идёт `PROMPT` к модели — придётся подождать, пока модель ответит.

**5. Сохраняйте результаты в отдельную папку.**

Не перезаписывайте исходные файлы. Всегда сохраняйте в `D:\output\…`, а не в `D:\input\…`.

**6. Используйте `{{date}}` и `{{timestamp}}` в именах.**
```
SAVE D:\output\report_{{date}}_{{timestamp}}.md
```


Так вы не перезапишете результат предыдущего запуска.

**7. Проверяйте `context` через промежуточный SAVE.**

Если что-то идёт не так — сохраните результат между шагами:
```
READ file.txt
PROMPT Обработай
SAVE D:\debug\step1.txt
# Проверь содержимое step1.txt, потом продолжай
PROMPT Обработай ещё
SAVE D:\debug\step2.txt
```

## Ограничения

- **Асинхронности нет.** Все шаги идут последовательно. Нельзя запустить два `LOOP` параллельно.
- **Модель не «помнит» предыдущие шаги.** Каждый `PROMPT` отправляет только текущий `context`.
- **Файлы >5 МБ не читаются** автоматически — их нужно обрабатывать частями.
- **Изображения не поддерживаются** — только текст и документы.
- **Один поток.** Пока скрипт работает, обычный чат недоступен для отправки сообщений (можно переключаться, но отправка заблокирована).

## Куда сохраняются скрипты

Все скрипты хранятся в файле `scripts.json` в корне программы. Можно:

- **Открыть в проводнике** — отредактировать вручную.
- **Скопировать** — поделиться с другими пользователями Echos.
- **Импортировать** — просто подложить чужой `scripts.json` вместо своего.

Формат простой:
```json
[
  {
    "name": "Мой скрипт",
    "body": "READ D:\\file.txt\nPROMPT Обработай\nSAVE D:\\out.md"
  }
]
```
